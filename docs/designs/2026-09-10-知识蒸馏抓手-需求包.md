## 1. 可验收目标

1. `skills/knowledge-distill/SKILL.md` 就位并可被 dsh 宿主发现（junction 挂载实测出现在会话技能列表）；
2. 台账三件套就位：`architect-knowledge/source-manifest.yaml`、`architect-knowledge/review-queue.yaml`、五个目录 `index.md`；存量 16 条条目按**实际 frontmatter status** 100% 登记（不猜测）；
3. `architect-knowledge/README.md` 增补「台账与索引」节，SKILL 阅读路径引用 index；
4. 一次蒸馏走查（对一篇既有文章/复盘做演练或主人投递的新文章，见 Q1）全程落库：条目 `status: 待审核` + 四台账齐备；
5. 主人按五问验收（自报 ≠ 完成）。

## 2. 范围（Do）

- SKILL 正文：输入源泛化（公众号文章 / 历史技术方案 / 串讲 / 复盘文档）；流程 = 探测桥 → 采集 → 图示解读（`evidence/images/` + manifest）→ 领域判定 → 五类落库（`status: 待审核`）→ 台账登记 → git 中文提交 → 主人确认后升级；
- 台账 schema 与存量补登记；五目录 index.md（条目 | 一句话定位 | 状态）；
- README 增量；SKILL 挂载沿用既有三技能布局（canonical `skills/` + 4 处镜像副本 + `$DSH_HOME/skills` junction）。

## 3. 不做项（Don't）

- **不做 knowledge-lint 机械校验**（P1-1 未立项；台账 schema 先行定义，留作其将来校验对象）；
- **不修改三个既有 SKILL 正文与知识库条目正文**（只增台账与 index；条目仅登记不改写）；
- **不主动采集新文章**（演练源用既有材料，新文章蒸馏待主人投递另跑）；
- **不建看板任务、不写分身记忆**（建设会话角色纪律；执行方式见 Q2）；
- **不引 RAG / MCP / 代码**（母包 §1.3 显式不做项）。
