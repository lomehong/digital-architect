# 知识库是多场景 Agent 基建（架构师职能扩展路线）

## 设计与排查共享同一底座（§7）

- 技术方案设计 = 从需求**向未来推演**（能力落在哪条链路、改后影响什么）；线上排查 = 从现象**向过去回溯**（问题经过哪些服务、哪个配置/缓存/消息/下游可能异常）；
- 两者共享四件套：**业务元语**（问题究竟指什么）→ **场景映射**（找入口）→ **架构图谱**（定位跨服务链路）→ **服务知识**（查状态机/配置/缓存/降级）；
- 结论：知识库投入不止服务「让 AI 写代码」，是研发调研、技术方案、代码修改、线上排查、事故复盘、新人理解系统的共同底座——一次显式化，多环节复用。

## 职能扩展路线（§8）

- 技术方案设计 Agent → 架构师 Agent 的扩展方向：**需求增强、跨系统影响分析、架构评审、线上问题排查、Coding Agent 任务规划与技术约束**；
- 扩展方式：在当前基础上**赋予对应 MCP**（如排查=LogHouse MCP + Service Runtime MCP）即可扩展能力边界——核心能力是同一种：**理解复杂系统，并基于真实的业务、架构和工程事实完成判断**。

## 需求增强的职责归属（§6.2，开放争议）

- 归属研发派：需求增强依赖技术系统现状分析，产品缺技术判断力；
- 归属产品派：需求增强本质是「改需求」，研发无权单独改；
- 作者主张：**架构师 Agent 适合承接**（具备技术方案设计能力后自然延伸）——文章留作开放问题。

## 本仓落点与边界（适用范围）

架构评审职能已具备（architect-review）；需求增强、排查场景**未启动**——属母包 P3（挂起，待知识共享 federation 方案落定后另议）。本条目只立知识，不构成启动依据。
