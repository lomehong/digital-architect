## 0. 迁移语义与总原则

- **迁移的是「平台常驻位置」**：大脑仓仍在 GitHub（多副本经 git 同步），实例宿主原地不动；事件契约是唯一真实数据面，各宿主改为**认证 HTTP 上报**（本机文件约定与 agent.db 摄取降级为「同宿主优化」）。
- **数据根 = 一切运行时状态**（instances/events/approvals/archive/govern-orders/config/brain-mirror）。迁移 = 搬数据根 + 换启动参数，代码包本身无状态。
- **云主机 = 非回环部署 → 受保护模式强制**（缺 `--admin-token` / `--yufu-url` 拒绝启动，不得半暴露）。
- ⛔ 通用纪律在云主机同样适用：不开多余端口、不注册 Windows 计划任务/隐藏窗口（本机杀软教训）；Linux 云主机常驻用 systemd（§5），Windows 宿主如需自启属**安全姿态变更须主人同意**并配杀软排除项。

## 1. 凭据清单（先备齐再动手）

| 凭据 | 用途 | 生成/存放 |
|---|---|---|
| `--admin-token` | 云主机看板查看/治理（所有读/写端点） | 长随机串；只进平台启动环境；泄露即换 |
| `--yufu-url` | 御符 Hub 地址（上报者 token 验证 + governor 领单/回执认证） | 现役御符地址；云主机须能访问 |
| `OBS_BRAIN_TOKEN` | 大脑仓 git 镜像拉取/推送 | GitHub **fine-grained PAT**：仅 `digital-architect` 仓，Contents Read/Write；只进平台进程环境（askpass 消费，不落盘/不进 URL） |
| `GOV_SIGN_KEY` | 治理指令单 HMAC 签名 | 长随机串；**平台与每台 governor 宿主共享**；泄露=伪造指令单风险，立即轮换 |
| `YUFU_CREDENTIAL` | governor 领单/回执的御符 token（宿主侧） | 各实例宿主自身御符 token，只进 governor 进程环境 |

## 2. 云主机部署步骤（可执行清单）

> 前提：云主机 Linux（Ubuntu/Debian 系示例），可出网访问 GitHub 与御符 Hub；安全组仅放行 SSH + 平台端口（默认 8787，建议限源 IP）。

1. **Node ≥ 22.5 LTS**（`node:sqlite` 为硬依赖——运行时视图摄取 agent.db 用；云主机上该源通常 disabled，但 import 不能缺）。
2. **取包**（二选一）：
   - git：`git clone https://github.com/lomehong/digital-architect.git /opt/architect`（含 observatory/ 源与知识库工作副本）；
   - tarball：本机 `node observatory/pack.mjs` → 传 `observatory/dist/architect-observatory-1.0.0.tgz` → 云主机 `tar -xzf` 解到 `/opt/observatory`（推荐：包自足，不依赖仓目录）。
3. **数据根**：`mkdir -p /var/lib/observatory/config`；从包内 `config/` 复制起始模板：
   - `alert-rules.yml`：按需调整（默认 5 条可直接用）；
   - `data-roots.yml`：登记实例 → 台账根（**云主机视角不可达的远端路径不要登记**——登记即视为真实台账，本地治理路径会被 confirmReal 门拦；跨宿主治理走 governor 指令单）。
4. **历史数据迁移**（可选）：本机停服后整目录拷贝 `E:\...\digital-architect\obs\` → `/var/lib/observatory/`（追加型数据，直接并；封印链随文件走，`seal.mjs --verify` 应 PASS）。全新冷启则跳过。
5. **凭据落位**：`/etc/observatory.env`（root:600）写入 `OBS_BRAIN_TOKEN=...`、`GOV_SIGN_KEY=...`（systemd `EnvironmentFile` 加载；不进 shell 历史/仓库）。
6. **首启（前台验证一次）**：
   ```bash
   cd /opt/observatory && set -a && . /etc/observatory.env && set +a
   node server.mjs --host 0.0.0.0 --port 8787 \
     --data /var/lib/observatory \
     --admin-token <管理令牌> --yufu-url <御符Hub地址> \
     --brain https://github.com/lomehong/digital-architect.git \
     --tasks "<云主机本地可达的台账目录>"   # 通常省略：远端台账由 governor 治理
   ```
   非回环绑定 + 双令牌齐备 → 受保护模式启动；`--brain` 触发镜像首克隆。
7. **验证清单**（全过才算迁移完成）：
   - `curl -H 'x-obs-admin: …' http://127.0.0.1:8787/api/health` → `ok:true`、`sources.brain=ok`、无 token 访问 → 401；
   - 无管理员令牌带外访问 → 401；伪造 Bearer 上报 → 401（负测必须做）；
   - 看板知识视图：全量条目 + 「大脑仓镜像」徽标（分支/head/同步时间）；
   - 指令单负测：错签名 governor 领单 → 拒绝 + critical 事件；
   - 实例宿主改用 HTTP 上报：`POST /api/events` 带 `Authorization: Bearer <御符token>` → 快照可见且 `verifiedAs` 注记在。
8. **systemd 常驻**（§5 模板）→ `systemctl enable --now observatory`。

## 3. 实例宿主侧改造

| 宿主 | 改造 |
|---|---|
| omp 容器 / dsh 会话 | 上报从「写仓内 obs/ 文件」改为 `POST https://<云主机>:8787/api/events`（Bearer 御符 token）；omp entrypoint 心跳与 yuyi-transcribe 协作转写循环改为 `--http` 模式或保留本地文件+同宿主摄取（本机试点期可逐步切） |
| 跨宿主治理 | 宿主上以 governor.mjs 领单：`GOV_SIGN_KEY`（与平台同值）+ `YUFU_CREDENTIAL` 环境变量；`--allow-root` 限定可治理项目根；可见终端启动（`--interval-sec 15`） |
| 本机旧平台 | 云主机验收通过后**停用**（按 `obs\server.pid` 精确停）；仓内 obs/ 保留为历史归档 |

## 4. 镜像分叉收敛手册（评审遗留闭环）

触发：看板知识视图出现「与远端分叉」/ 知识升级回执「已拒写」（critical 事件）。平台**永不自动强推/改历史**，收敛由主人执行：

1. 云主机上 `cd /var/lib/observatory/brain-mirror && git log --oneline -3` 与 `git log --oneline brain/main -3` 对比分叉点；
2. 判断远端新提交是否应保留：
   - **远端为准**（他副本的正常推进）：`git rebase brain/main`（把平台拒写的本地提交重放）→ 解决冲突 → `git push` → 平台下一周期自动恢复，重发被拒的治理操作；
   - **镜像为准**（远端被误改写，罕见）：主人确认后 `git push --force-with-lease brain HEAD:main`；
3. 收敛后：快照徽标回「与远端一致」→ 重新执行原治理操作（新单号）。
4. 全程留痕：收敛属人工 git 操作，建议主人在治理结果栏注明「镜像分叉已收敛（<commit>）」。

## 5. systemd 单元模板（Linux 云主机）

```ini
# /etc/systemd/system/observatory.service
[Unit]
Description=Architect Observatory
After=network-online.target
Wants=network-online.target

[Service]
User=obs
EnvironmentFile=/etc/observatory.env
WorkingDirectory=/opt/observatory
ExecStart=/usr/bin/node server.mjs --host 0.0.0.0 --port 8787 --data /var/lib/observatory --admin-token ${OBS_ADMIN_TOKEN} --yufu-url ${OBS_YUFU_URL} --brain https://github.com/lomehong/digital-architect.git
Restart=on-failure
RestartSec=5
# 加固：只读系统目录 + 私有临时
ProtectSystem=strict
ReadWritePaths=/var/lib/observatory
PrivateTmp=true
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

> governor 宿主侧**不建议** systemd 常驻试点期常开：治理是主人随需动作，可见终端 `node governor.mjs …` 按需启动即可；试点稳定后如需常驻再立单元（属常驻策略变更，向主人报备）。

## 6. 已知约束与降级（云主机上如实预期）

| 面 | 云主机预期 |
|---|---|
| 运行时视图 | `agent.db` 为 omp 容器本机文件，云主机不可达 → runtime 视图 disabled（显式降级，非故障）；omp 宿主侧可转写为事件上报补足 |
| 御驿协作面 | `~/.yuyi` 本机摄取同上；**实例侧转写已实施**：宿主跑 `yuyi-transcribe.mjs`（随包）转写 `collab.*` 事件，文件约定或 `--http` 认证上报 |
| 台账本地治理 | `--tasks`/data-roots 只覆盖云主机本地可达路径；跨宿主治理一律走指令单 |
| 审批代办 | 挂单文件在数据根 → 云主机集中；实例侧写决定文件改为调 API（与上报同认证） |

## 7. 回滚

云主机异常时：`systemctl stop observatory`（或停前台进程）→ 本机旧平台按原命令重启（仓内 obs/ 数据仍在）→ 实例宿主上报目标切回本地。数据根互相独立，无格式迁移，回滚零损失。
