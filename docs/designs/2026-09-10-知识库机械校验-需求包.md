## 1. 可验收目标

1. `lintKnowledge` 纯函数落位 dsh-architect（`src/lint.ts`）：规则覆盖 frontmatter 必填字段 / status 枚举 / confirmed 日期格式 / 来源非空与本地路径可解析提示 / review-queue ↔ frontmatter 双向一致性 / index ↔ 条目一致性；
2. 零依赖 CLI（`scripts/lint-knowledge.mjs`）：对 `architect-knowledge/` 全库执行收集 → 校验 → 报告，解析失败报错不猜测；
3. dsh-architect v0.2.0：vitest 单测全绿（含 8 类破坏样本逐一检出）、既有 24 测试零回归、exports 增 `./lint`；
4. 本仓 CI 新建（`.github/workflows/ci.yml`）：检出子模块 → 构建 → 对本知识库跑 lint；
5. 主人五问验收。

## 2. 范围（Do）

- 规则集（机械可判定，零语义判断）：R1 必填字段（title/domain/source.origin/source.ref/confirmed/status/owner）；R2 status ∈ {已确认, 待审核}；R3 confirmed 为 YYYY-MM-DD；R4 review-queue ↔ 待审核条目双向一致；R5 各目录 index ↔ 条目双向一致（文件存在 + 状态一致）；R6 owner 非空；R7 ref 含仓内相对路径时提示 CLI 存在性核查；R8 解析失败即 error（不猜测不跳过）；
- CLI 收集器：walk 五目录（跳过 index.md、evidence/）+ 解析两台账（受限格式解析，覆盖 P0 已定 schema）；
- 两仓 CI 接线（dsh-architect 既有 CI 的 vitest 自动覆盖新 spec；本仓 CI 新建）。

## 3. 不做项（Don't）

- **不加第 4 个模型工具**：lint 的消费面是 CI 与命令行（node 即跨宿主），模型传参形态不经济；将来需要时按 tools.ts/omp.ts 既有模式扩展（显式登记，非遗漏）；
- **不改既有三工具与 service 语义**（纯新增，v0.1.x 行为零变化）；
- **不查 `docs/designs/`**：方案文档已有 architect_design/review 结构检查，职责不重叠；
- **不做正文语义校验**（「内容对不对」归人评与回源核查，lint 只守结构——文章 §5.4 边界）；
- **不引入新 npm 依赖**（CLI 手写受限解析器，维持零依赖纪律）。
