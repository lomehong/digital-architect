# Runbook：公众号文章采集管道（外部知识蒸馏入知识库）

> 阶段 4 交付。目标：把外部公众号文章（方法论/复盘/案例）持续蒸馏进 `architect-knowledge/`。
> **红线：微信反爬——服务端直抓会撞验证墙，必须走浏览器桥（真实会话指纹）。**

## 前置条件

| 项 | 状态 |
|---|---|
| 浏览器桥 | Lum1104/dsh-browser 已装（桥插件 bundle + Chrome 扩展 `$DSH_HOME\browser-extension`）；扩展地址设置一次即持久 |
| 桥配置探测 | `GET http://127.0.0.1:3088/ext/bridge-config` → `{"wsUrl":"ws://127.0.0.1:3088/ext/bridge"}`（能返回即桥在位） |
| 登录态 | 微信公众号文章在桌面浏览器有真实会话（文章页一般免登录；号内搜索/历史页需要） |

## 采集流程（每篇）

1. **探测桥**：请求 bridge-config，确认 wsUrl 在位；不在位 → 先启动桌面浏览器并确认扩展已连接，不绕过。
2. **打开文章**：经浏览器桥打开公众号文章 URL（主人投递或白名单源），等待加载完成。
3. **抽取文本**：用浏览器文本快照读正文（标题/作者/发布时间/正文/代码块）。
4. **图示解读**：正文截图逐张读图（宿主支持图片附件；本地图片用 read_image），把图示知识并入条目——**文章后半部常以图示承载核心内容**（两篇文章入库实证：架构师流水线/六维度全在图 7/图 8）。
5. **蒸馏入结构**：按 `architect-knowledge/README.md` 条目格式落库：
   - `status: 待审核`（未确认内容不得静默升级为事实）；
   - `source.origin/ref` 必须带公众号名、作者、发布日期、原文 URL；
   - 方法论 → `principle/`；事故/复盘 → `practice/`；外部领域契约 → `reference/`（引用不复制）；
   - 同时按替代语义写入 dsh-memory（`statementType: 事实`，待审核内容在文内标注）供分身检索。
6. **登记与提交**：知识库 git 中文提交；主人确认后条目 status 改 `已确认`。

## 维护纪律

- 周期校准：大版本/复盘资料采集后，对照已有条目做知识漂移检查（`practice/knowledge-drift-cases.md` 的回写机制）。
- 每条外部知识必须可回源到 URL；图示解读注明「图 N 多模态解读」。
- 采集失败（验证墙/桥断开）如实记录并停止，**不换非浏览器手段重试**（红线不可绕）。
