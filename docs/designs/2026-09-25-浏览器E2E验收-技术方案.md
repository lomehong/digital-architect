# 可执行技术方案：架构师 Agent 真实浏览器端到端验收能力

## 0. 一句话与五问速答

为架构师 Agent 新增「像人一样打开浏览器做验收」的边缘能力：jev-ultrafast 循环（MIT）+ 本地 Laya 决策服务（Apache-2.0，cklxx/laya-browser v10s 权重）+ 独立 Chrome 实例，全链路无数据出域；作为 architect-implement 验证覆盖的新执行手段，产出可复跑证据，验收语义不变（自报≠完成）。

| 五问 | 速答 |
|---|---|
| 改哪里？ | 新增 `browser-acceptance/` 薄能力包（部署脚本+运行器+基线套件）；Extend `skills/architect-implement`（登记新验证手段类型与红线）；回写 `adapters/oh-my-pi.md`；知识库 practice 回灌（确认后）。核心流程语义、packages/architect-core、observatory、dsh-suite 均不动 |
| 为什么改？ | 验证覆盖维度缺执行手段：现状验收只能跑 bash 单测（explore 实证：13 个技能无浏览器/E2E 能力），无法覆盖「像人一样操作系统」的验收场景 |
| 影响谁？ | architect-implement 执行面（新增手段类型）、适配层（工具面回写）、目标项目验收环节（获得新证据形态）；缺席降级 = 退回既有 bash 单测验收，不阻塞流程 |
| 如何验证？ | 部署后复跑 Spike 基线：七任务套件 ≥15/21 且导航类 3/3；组件门禁 = jev 31 单测 + 21 守卫检查 + laya verify.py；契约 = systemone 端点格式测试 |
| 还有什么没有确认？ | B1/Q3/Q4/Q5 已决策（见 §8）；余 2 项 Unknown 维持登记：Q1 宿主适配缺口、Q2 五层落点归属 |

### 0.1 链路与差距分析（Gap Analysis）

调用链（新增边缘，不侵入核心）：

```
architect-implement 验证清单（验收类条目）
  → browser-acceptance 运行器（自然语言目标 + 独立校验表达式）
    → jev-ultrafast 循环 ──决策──→ 本地 Laya systemone 服务（v10s，127.0.0.1 环回）
      │                  └──文本──→ DeepSeek 端点（仅 TYPE_TEXT，环境变量授钥）
      └── CDP ──→ 独立 Chrome 实例（独立 user-data-dir，主人浏览器不受扰）
  → 证据落盘（轨迹 JSON + 独立校验结果 + 可选截图）→ 自报 → 主人 confirm
```

对照 `reference/dsh-suite-architecture-map.md` 逐项判定：

| 能力 | 判定 | 依据 |
|---|---|---|
| 浏览器执行/决策栈 | **Build**（封装外部件，非自建算法） | 体系内无任何浏览器**验收执行**能力（13 个技能逐项核查：knowledge-distill 仅引用外部采集桥 dsh-browser、archify 仅有截图类证据读取，均非验收执行手段；adapters/ 工具面零命中）；dsh-browser 职责是反爬采集而非验收（suite-build-lessons:36），不可复用 |
| 验收流程语义 | **Reuse** | architect-implement「测试清单先行/红灯不提交/对照自检」原样承载，只新增一种手段类型 |
| 决策门/任务面/记忆面 | **Reuse** | 走宿主适配层既有映射，不发明新基建（D12） |
| 证据校验/评分 | **Reuse** | 覆盖率评分仍走 packages/architect-core 纯函数（D11），本方案不加评分逻辑 |
| dsh-regression（会话回归） | **并存不动** | 它驱动真实会话做回归，本能力做浏览器 UI 验收，分工不同，互不依赖 |
