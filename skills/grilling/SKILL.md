# grilling · 拷问原语

你承担**拷问原语**职能：对需求/方案/决策发起无情但礼貌的结构化问询，直到**设计树闭合**——每个分支要么已裁决、要么已登记为决策门。对齐后才准出。

## 输入

- 拷问对象三选一：**需求**（主人提出的研发编排类需求）/ **方案**（技术方案或设计草案）/ **决策**（待定的取舍点）；
- 已有材料：对话记录、草稿文档、可查证的代码库与环境（事实自取的来源）。

## 流程

### ⓐ 建设计树与 frontier

把对象拆成决策分支：每个分支挂子决策，形成树。**frontier** = 前提已定、当前可问的分支集合。首轮提问前先列树，再从 frontier 取问题；每次裁决后刷新 frontier。

### ⓑ 轮次执行

1. **整轮编号提问**：一次列出本轮全部问题（编号），主人可逐条作答；
2. **每问带推荐答案**：给出你的倾向与理由；措辞让「是」即接受推荐，降低作答成本；
3. **等待作答**：发出后停下等待，不自行脑补答案；
4. 每轮收尾：登记各分支新状态；本轮新增或锐化的术语即时写入 `architect-knowledge/meta/glossary.md`（一行索引+权威定义指针），不等会话收尾。

### ⓒ 事实自取

环境能查到的事实（代码行为、配置、文档、命令输出）派子代理查证，不问主人；**决策必须归主人**。查证结论注明出处（命令/文件），回填对应分支。

### ⓓ 树闭合判定

逐分支归类，只有三种合法状态：**已裁决**（主人作答）/ **待门**（转决策门，附已知与建议）/ **事实待查**（派查证）。出现「不知道算哪类」的分支，本身就是一个待澄清问题，先解决归类再继续。

### ⓔ 轮次上限

3 轮未闭合 → 未决分支整体转决策门 `ask` 主人，一次性呈报（每分支附当前已知与推荐），**不再追问**。

### 完成判据（两杠杆）

- **Clarity**：frontier 为空——每个分支要么已裁决、要么已登记为决策门，无静默假设；
- **Demand**：每个分支状态显式登记（裁决/待门/事实待查三类）+ 本轮新术语已落 GLOSSARY。

## 治理不变量（本技能语境的操作化；权威定义见 `architect-knowledge/principle/task-and-memory-surface.md` 与流程 K 各 SKILL.md）

| 不变量 | 在本技能中的生效方式 |
|---|---|
| 自报 ≠ 完成 | 本技能无产出交付，不适用任务面 report；树闭合结论属会话内对齐，不等于任何下游环节放行 |
| confirm 归主人 | 每轮答案与树闭合判定均经主人确认；推荐答案被「是」接受才算裁决 |
| 治理动作不静默 | 3 轮上限 → 转决策门 `ask`，不静默追问；不把待决策项悄悄替主人拍板 |
| 证据回源 | 每分支状态有登记出处（主人作答 / 查证命令输出 / 已登记的决策门） |

## 与流程 K 的衔接

- 流程 K `architect-prd-digest` 第二步（需求拷问）在需求准入语境下调用本技能（3 轮上限同源）；
- 本技能可独立调用（任意会话需要对齐原语时）；流程 D 链路第一环（→ `spec-align`）。
