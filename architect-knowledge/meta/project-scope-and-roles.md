# 项目边界与角色纪律

## 项目一句话

基于数字分身套件已有的 Harness 机制（任务看板/账本治理/共享记忆/守卫纪律/验收语义）+ 两篇方法论文章，搭建**架构师 Agent**——从架构师核心职能「技术方案设计」切入，让 AI 完成跨复杂系统的技术方案设计。

## 目标

让大型存量分布式系统成为 AI 可理解、可推理、可验证的工程系统，使 AI Agent 能完成技术方案设计，进而迈向 7×24 无人值守。**第一个落地区域：数字分身套件与 dsh 宿主自身（自举）。**

## 项目边界

- 阶段 1：纯知识工程（本仓库文件），**零代码**、不写插件。
- 阶段 2：自举首跑验证流程（对分身发起，本建设会话不代跑业务机制）。
- 阶段 3：验证有效后由主人拍板，才插件化（dsh-architect）。
- 阶段 4：service-knowledge 生成、外部知识管道。

## 角色纪律（任何会话必须遵守）

1. **执行会话自报、主人确认**——任何会话不代劳别人的角色动作；建设/保障会话不触发业务机制（不建看板任务、不写分身记忆）。
2. **一切知识进结构**：工作必须有看板痕迹与知识库痕迹；无痕迹的工作等于没做。
3. **自报 ≠ 完成**：只有主人确认才落定并沉淀「已验证结果」。
4. **机制优先于人工**：发现流程缺口先修机制，不用手工搬状态顶替。

## 非同义词与易混概念

| 术语 | 含义 | 不是什么 |
|---|---|---|
| 架构师 Agent | 分身的新能力（SKILL 流程 + 工程知识库） | 不是第二只分身，不是新 Agent 程序 |
| architect-knowledge | 工程知识库（业务/架构知识） | 不是分身的人格记忆（那是 dsh-memory） |
| 技术方案 | 六维度+五问的可执行设计文档 | 不是 PRD，不是代码 |
| 人工决策门 | Unknown/Conflict/业务取舍/跨团队承诺/合规/高风险变更六类 | 不是每一步都要人批 |
