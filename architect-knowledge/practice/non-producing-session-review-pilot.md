# 非产出会话评分复核：G4 首试的操作面与边界

## 适用范围

方案完备度基线（docs/metrics/方案完备度基线.md）的「内容分须经非产出会话复核」（rubric v1.1）场景；机制出处为「评审口径统一与机制收口」（09-11）Do-4。

## 试点结论（U1 回灌：复核常态化路径）

「评审口径统一与机制收口」（09-11）行内容分 56/60 由非产出会话（2026-09-22 唤醒复核）独立复核通过并登记为终值——非产出会话承担 G4 复核可行，U1（复核常态化依赖非产出会话可用）在此实测闭合。

## 操作面（本次实证的四步）

1. 身份前提：复核会话未参与被评方案的产出（唤醒会话天然满足）；
2. 材料自足：方案 + 评审结论 + 基线行三件即可复核，无需产出会话交接；
3. 方法：逐格独立对照 rubric 评分 → 与自评比对 → 对每条扣分理由回源抽查（本例 4/4 属实）→ 证据引用抽验（含用 git 历史版本直接验实「修复前口径分裂」这类关键证据）；
4. 登记：只填复核者/复核结果两列并追加复核注记，分数与历史行不回改（append-only）。

## 边界与局限（如实登记）

- 历史版本取证依赖本机工作副本与 git 历史在场；工作副本缺席时只能以同期文档互证（本次「子模块匿名可达」一条即属此类，未重跑网络实测）；
- 复核者可登记观察项但不当场处置（本次发现的 09-14/09-18 基线行缺口，留给产出会话补登）——复核与产出分离，复核者不越权改史；
- 结构分不重测（检查器版本随时间演进，重测非同时点对照）；复核对象是内容分（rubric v1.1 语义）。
