# 多会话共享工作树的提交纪律（git add -A 卷稿事故）

## 事故经过

- 本会话（架构师建设线）在 digital-architect 工作树逐步落盘 P0 产物，尚未提交；
- 并行的 docker/omp 建设会话提交（`0319b3c`「docker：构建全面国内网络优化」，2026-09-10 23:20）执行了 `git add -A`，把本会话**未完成评审的中间态**（知识台账、三份设计文档、SKILL 等 18 个文件）一并卷入其提交；
- 结果：内容终态无损（本会话后续增量提交 `3b5f080` 补齐并推送），但**提交归属与内容错位**——按提交标题回溯找不到知识产物，审计链受损。

## 教训

1. **多会话共享工作树时，提交一律按显式路径 `git add <path...>`，禁用无差别 `git add -A`**；或提交前 `git status` 逐文件认领自己的清单；
2. 暂存区混入他方文件时，拆分提交或还原他方文件，**不得静默打包**；
3. 提交标题必须与内容对得上——审计以提交为锚，标题错位会让回溯失效（与 `knowledge-drift-cases.md` 的「可回源」精神同源）。

## 适用范围

一切多会话并行开发同一 git 仓库的场景（本套件常态：建设线 / 业务线 / 容器线并行）。
