## 4. 风险覆盖（10 分）

| 风险类 | 有无涉及 | 分析与对策 |
|---|---|---|
| Compatibility 兼容 | 有 | 新 SKILL 纯增量；review SKILL 新增节不改变原评分语义；fail-fast 改变启动失败模式（更早更明确），需红绿双态实测确认正常路径不受影响 |
| Exception 异常 | 有 | fail-fast 检测逻辑须防误判：仅当 `DEEPSEEK_API_KEY` 为空或以 `PLACEHOLDER` 开头时拒绝；其余一律放行（宁可漏判不误杀）；脚本 set -e 下用显式 if |
| Cache 缓存 | 不适用 | 无缓存面 |
| MQ 消息 | 不适用 | 无消息面 |
| State 状态机 | 有 | 知识条目 status 待审核→已确认（不跳步）；分支状态：feature → 验证 → 合并 main |
| Security 安全 | 有 | fail-fast 提示不得回显密钥值；仅提示「未配置或仍为占位符」 |

## 5. 验证覆盖（10 分）

| 验证手段 | 内容 | 可执行入口 |
|---|---|---|
| Unit 单测 | SKILL 无单测面；fail-fast 以 shell 逻辑为主，用容器实测替代 | — |
| Contract 契约 | 三副本一致性（G3 脚本）；SKILL frontmatter（name/description 必填，确认 omp 可发现） | `node scripts/check-skills-sync.mjs` |
| Regression 回归 | lint 全绿（条目 24、queue 一致）；dsh-architect 47 测试不受影响 | `node dsh-architect/scripts/lint-knowledge.mjs` + `npm test` |
| Monitoring 监控 | CI 双 job（lint + 副本校验）持续把关 | GitHub Actions |
| Rollback 回滚 | 分项 commit；试点分支 `feature/TB-…-entrypoint-failfast` 未合并前可弃；合并后 git revert | git |

**试点红绿双态（关键验收）**：
- 红：`DEEPSEEK_API_KEY=PLACEHOLDER-xxx` 启动 → 容器退出码非 0，日志含可读提示；
- 绿：真实密钥启动 → 正常运行（进入 supervisor 日志 + omp 可用）。
