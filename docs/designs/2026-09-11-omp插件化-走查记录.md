## 五、插件目录挂载收口（2026-09-11，主人指出）

主人指出 omp-architect 应挂载到容器中 omp 的**插件目录**（而非 agent-tools 转发）。已核实官方契约并收口：

- **插件契约**（docs/plugin-manager-installer-plumbing.md）：插件 = `package.json#omp.extensions` 声明扩展入口；本地路径安装走 `PluginManager.link()`；用户插件数据根 `~/.omp/plugins`（node_modules + omp-plugins.lock.json）。
- **改造**：omp-architect `package.json` 增 `"omp": { "extensions": ["src/extension.ts"] }`；新增 `src/extension.ts`（ExtensionAPI 入口：`pi.registerTool` 注册 4 工具，zod 兼容 builder 与 custom-tools 同族）。
- **挂载/安装**：`omp plugin link /opt/architect/omp-architect`（link 状态持久于 docker/omp/plugins）；**agent-tools 转发退役**（compose 移除挂载），插件成为工具面唯一承载——实测退役后 4 工具仍全在且 `architect_lint` 实跑 PASS（27 条，含另一会话新增待审核条目）。
- **升级语义**：核心/工具更新 → 改仓库 + push；link 指向 /opt/architect 源码，容器内即时生效，无需重装。

**遗留**：F2 旧 omp 单测（tests/omp.spec.ts 存根已在迁移中移出）需在 omp-architect 仓重建为 vitest 用例（4 工具红绿）。
