# 数字分身套件联邦原则（宪法四条与合规细则）

> 本条目是 dsh 生态做任何技术方案时**必须遵守的架构约束**。完整原文以宪章为准（引用不复制）。

## 联邦四原则

1. **加载独立**：套件插件之间不得存在加载期依赖——禁止对其他套件包的顶层 import 与硬 `inject`。对宿主（`@deepseek-ai/dsh-*`）的注入不受此限——那是平台，不是邻居。
2. **运行独立 + 显式降级**：核心功能必须在任何兄弟插件全部缺席时完整可用；增强能力缺席时**显式降级**（UI 标注/日志说明/能力收窄），不得抛错阻断核心路径，也不得静默假装能力存在。
3. **数据自治**：插件只把数据写进 `$DSH_HOME/<插件id>/`，不写兄弟插件目录；跨插件数据引用只经服务接口或模型工具约定。默认实例级路径，机器级例外必须 README 标注理由。
4. **安装独立**：安装器只是便利；每插件可单独安装并独立发挥声明的能力。

## 跨插件协作唯一合法形态：可选增强

两种允许的签名：
1. **服务惰性解析**：`ctx.get('<sibling-service>')` 返回 `undefined` ⇒ 走降级分支；
2. **预设/能力条件装配**：检测到兄弟包已安装才追加配置行（「装了才有行，没装预设依然可用」）。

禁止：`@dsh-extra/*` 值导入、inject 套件服务名、peerDependencies 硬依赖表达可选增强。类型共享只允许 `import type`（构建期擦除）。

## 显式降级三要素

1. **可发现**：用户能在 UI 看到「某增强未安装」（空态/徽标/WARN），不是报错堆栈或无声缺失；
2. **安全收敛**：降级行为默认收敛到更保守的一侧——**治理类增强缺席时不得扩大权限面**（无账本 L2 = 拦截 + 尽力通知，不是放行）；
3. **可恢复**：兄弟插件后装/重载后，增强能力应在下一次探测/轮询自动恢复。

## 治理与身份

- **治理自治**：账本（L0-L3）是可选治理层；缺席时按预定义本地策略收敛（保守侧）并显式告知；治理缺席不得成为核心功能不可用的理由。
- **身份自治**：渠道类用渠道 userId，web/预设类用 `'master'` 语义；dsh-actors 是可选身份增强，不得为其引入硬依赖。

## 准入检查（新插件/新方案 PR 逐项过）

- 无套件包值导入、inject 无套件服务名；数据目录 `$DSH_HOME/<插件id>/` 原子写；
- 核心功能兄弟全缺席可用；每项增强有显式降级；依赖矩阵已更新；README 含「单独安装」节；
- **改动仓测试全绿 + 工作区干净**（提交前纪律）；
- 客户端入口为命名导出 `apply(ctx)` + `inject` 声明，槽位经 `ctx.slots.inject()` 注册。

## 合规范本（照着写）

dsh-yuyi（零耦合标杆）、dsh-memory 早加载（服务型挂载范本）、dsh-twin 条件预设装配与转人工降级、看板↔账本两函数窄契约（`check`/`fillResult` + 惰性 `ctx.get`）。
