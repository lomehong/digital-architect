# 自进化系统的设计纪律（OpenEvolve 蒸馏）

> OpenEvolve：AlphaEvolve 的开源复刻（Apache-2.0）。核心循环 = 初始代码 + 评估函数 → LLM 当「变异机器」提出候选 → 机器打分 → 留优汰劣 → 下一代。

## 铁门槛：评估函数是前提

- 任务必须能**机器打分**（跑得快可测、结果对可测）它才吃得下；打不出分的（好看/用户喜欢）没辙；
- 真正决定谁留下来的**从来不是模型，而是评估函数**——LLM 只负责提出「这样改会怎样」的候选；
- **本仓互证**：knowledge-lint（结构可判定）/coverage（骨架分）/CI 门禁 = 已在给可判定维度机器打分；打不出分的（内容覆盖度/方案好不好）留主人——与「结构分 ≠ 内容覆盖度」双轨完全同构。

## 防过早收敛三机制

1. **岛屿模型**：种群拆五岛独立进化，每 20 代才迁移种子——防一窝蜂涌向单一方案；
2. **MAP-Elites 分区冠军榜**：按复杂度/性能/内存分区，每格留本区冠军，不只留全局第一；
3. **双选择采样**：给 LLM 的教材 = 3 份最优 + 2 份高差异，提示模板随机变体——前三个不跑偏，后两个出怪招。

## 省钱：五道闸级联评估漏斗

语法解析 → 预扫描 → 编译 → 检查 → 完整稳定运行，**便宜闸在前、贵闸只留幸存者**。本仓 CI 门禁序（构建→lint→副本一致→台账契约）同构。

## Artifact 侧信道：把摔跤记录给下一棒看

评估器把运行现场（报错/性能剖析/编译警告）打包传给下一代、塞进提示词——一般进化只传分数，这个侧信道传「为什么差」。

## 安全红线（本文最有价值的迁移）

**经典漏洞**：被进化的代码若能改动评估函数，会毫不犹豫把考卷改简单然后拿满分。OpenEvolve 用目录隔离+权限设计防，评估脚本的摆放与权限是使用者责任。

**本仓等价物与提案**：agent 会话可触达 lint 规则（R1~R9）、coverage 评分器、完备度基线 rubric、CI workflow——**修改检查器/门禁/基线以「自放水」的风险真实存在**。提案：此类变更一律视同**高风险变更**（主人审批 + 变更说明），禁止被检对象所在的执行会话顺手放松校验；本条目即红线提案，主人确认后可考虑在 CI/适配层落防护（如 workflows 与 lint 规则文件的变更评审要求）。

## 诚实边界与成本

- **进化就是会卡**：调温度/缩迁移间隔/保多样性/换模板/Artifact 找方向——只能缓解不能根治；
- **改变了什么**：把「发现算法」成本打到几十美元+一台笔记本；**没改变什么**：「什么算好、什么算对」这把尺子机器造不出来（≈ 内容分人评）；
- 成本分级：便宜模型（本地/Flash）跑 100–200 迭代看趋势 → 有戏再换强模型加注 ≈ 本仓「委托-把关」的模型分级思路。

## 本仓落点（适用范围）

1. **红线已落地**（2026-09-15，主人立项确认）：`scripts/gate-guard.mjs` + CI「Gate Guard」步骤——保护清单（workflows/core 评分器/lint CLI/基线）出现变更且提交无 `Gate-Approved` 标记 → CI 红灯；门禁脚本自指保护；
2. **Artifact 传递强化候选**：看板 task_report 失败时附结构化「摔跤记录」（错误分类/日志指针），下一棒认领即见——机制已大体存在，增量小；
3. **上下文采样纪律候选**：给设计/评审喂历史方案时按「最优+高差异」混合取样，防同质化；
4. **OpenEvolve 工具本身**：本项目暂无需要进化的热点数值代码，**不引入**；其价值在模式不在工具。
