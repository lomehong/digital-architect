# 技术方案：omp 脱敏扩展（omp-redact）

> 产出者：本会话（dsh 侧）· 日期：2026-09-18
> 需求包：`docs/designs/2026-09-18-omp脱敏扩展-需求包.md`（主人已确认准入）
> 实证基线：容器 omp 18.1.18 扩展 API 类型定义 + 运行时探针实测（本方案 §1.1 payload 形状为真机抓取）

---

## 0. 架构总览

单文件扩展 `omp-redact-extension.js`（yuyi 扩展同形态：`export default (pi) => {...}`），
源码落 digital-architect 仓 `extensions/omp-redact/`，构建产物部署两处：

```
容器：docker/omp/agent/extensions/omp-redact-extension.js → ~/.omp/agent/extensions/（现有挂载）
omo ：vendor/omp-redact-extension.js → install.sh 部署至 $HOME/.omp/agent/extensions/（容器架构师阶段 4）
状态：$HOME/.omp/redact/state.json（映射账本，0600）
配置：$HOME/.omp/redact/config.json（可选，缺省全内置启用）
```

数据流（挂点 = omp 扩展事件，全部为 owner 侧实现，无 omp 上游改动）：

```
agent 上下文 ──→ [before_provider_request] payload 深遍历掩码（真实值→[[CODE_N]]）──→ LLM provider
       ↑                                                                      │
       │                                                              响应（占位符形态）
       │                                                                      ↓
工具执行（真实值）←── [tool_call] {input: 占位符还原} ←── LLM 工具调用（含占位符）
       │
       └─→ 工具结果（真实值）进上下文 ──→ 下一轮请求再次过掩码（闭环）
```

## 1. 挂点实现

### 1.1 `before_provider_request`：出站掩码

实测 payload 形状（真机抓取，openai-completions 族）：

```json
{ "model": "…", "messages": [{"role","content": string | [block...]}],
  "stream": true, "tools": [{"type","function":{"name","description","parameters"}}],
  "max_completion_tokens": N, "reasoning_effort": "…" }
```

**遍历契约：形状无关深遍历**——递归遍历 payload 全部字符串值（对象键不掩码、值掩码；
数组逐项；content 为 string 或 block 数组两种形态统一覆盖；tools[].function.description
同为出站字符串自动覆盖），命中规则的真实值替换为占位符，**结构化重建后作为 handler
返回值**（`BeforeProviderRequestEventResult = unknown`，返回即替换）。

- 不特判 provider 族：anthropic/google 族 payload 形状不同，但深遍历天然兼容；
- 不跳过任何键：敏感模式（手机号/密钥等）不会命中 model id 等控制字段，无需白名单；
- 成本：单次 O(payload) 遍历 + 克隆，大上下文（MB 级）可接受；
- 幂等：占位符 `[[CODE_N]]` 本身不命中任何规则（引擎保证）——历史轮已掩码内容重掩不变。

### 1.2 `tool_call`：入站还原（功能性核心）

实测：事件键 `["type","toolName","toolCallId","input"]`——**不暴露原始 raw input**，
handler 只见规范化 `input` 视图。

**还原策略**：
1. 深遍历 `event.input` 全部字符串值，占位符 → 真实值（映射账本反查）；
2. 未发现任何占位符 → **返回 `undefined`（no-op）**：工具以原始 raw input 执行，零干预；
3. 发现占位符 → 深克隆 + 还原后作为 `result.input` 返回。

**边界与安全网**：`result.input` 是"raw execution input"，与规范化视图可能存在派生
gate-only 字段差异（omp 契约明示 hashline `edit` 的 `path/paths` 案例）；omp 契约同时
保证"revision 经 tool schema 重验后成为实际调度参数"——多余派生字段被 schema 校验
拦下，构成安全网。实现期补一条实机探针（edit 工具带占位符用例）验证该路径。

### 1.3 生命周期与会话分账

- 会话标识：`session_start` 事件从 ctx 取 sessionId（实现期探针确认具体字段；
  headless `-p` 模式同样触发 session_start）；取不到时落入 `default` 账本；
- 账本：`{sessions: {sessionId: {map: {占位符: 真实值}, lastActive}}}`；
- 持久化：防抖原子写（tmp + rename），文件 0600；
- 清理：会话 7 天不活跃或账本总数 > 200 自动清理（对齐 dsh-redact）。

## 2. 规则引擎（移植 dsh-redact `rules.ts`）

| 类别 | 占位符 | 匹配要点 |
|---|---|---|
| 密钥/凭据 | `[[SECRET_N]]` | sk-…、AKIA…、ghp_/github_pat_…、xox…-…、JWT、`Bearer <值>`、PEM 私钥块、`password/api_key/token… = 值`（保留变量名与协议前缀，只脱值） |
| 身份证 | `[[ID_N]]` | 18 位 GB11643 校验码 + 日期段验证；15 位一代证（日期段合理性） |
| 银行卡 | `[[BANK_N]]` | 13–19 位数字段 + Luhn 校验 |
| 手机号 | `[[TEL_N]]` | `1[3-9]` 开头 11 位，数字边界防截取 |
| 邮箱 | `[[EMAIL_N]]` | 标准邮箱 |

- 优先级收集、重叠区间先到先得：密钥 > 证件 > 银行卡 > 手机 > 邮箱；
- 脱敏幂等；编号按账本内该类别首现顺序；
- 自定义规则：名称 + 正则（≤200 字符、≤50 条，加载时编译校验，失败规则跳过并告警）；
  类别码取名称字母数字（`orderID` → `[[ORDERID_N]]`）；
- 实体别名：原词（字面量，长者优先）→ 固定替换词（≤100 条）；与敏感命中重叠时以脱敏为准。

## 3. 映射与持久化

state.json schema：

```json
{ "version": 1,
  "sessions": { "<sessionId>": { "map": { "[[TEL_1]]": "138…", "…": "…" }, "lastActive": 1789695385000 } } }
```

- 写路径：`$HOME/.omp/redact/state.json`（容器 /home/pi/.omp/redact/；omo 重定向 HOME
  后落 ~/.omo/home/.omp/redact/——两部署面同一相对路径）；
- 目录 0700、文件 0600；写入防抖（脏标记 + 定时/退出刷盘）+ 原子替换；
- 清理：加载时惰性清理（7 天不活跃会话剔除；账本总量 > 200 淘汰最旧）。

## 4. 配置 schema（`$HOME/.omp/redact/config.json`，可选）

```json
{ "enabled": true,
  "restore": true,
  "categories": { "secret": true, "id": true, "bank": true, "tel": true, "email": true },
  "customRules": [ { "name": "orderID", "pattern": "ORD-[0-9]{8}" } ],
  "aliases": [ { "from": "腾讯", "to": "某公司" } ] }
```

缺省（无文件）= enabled/restore true + 五类全开。加载时校验（同 dsh-redact 设置页规则），
非法条目跳过并经 `pi.on` 可用通知渠道告警（stderr）。

## 5. 已知边界与威胁模型（继承 dsh-redact，README 明示口径）

- **防谁**：模型厂商边界。出站 payload 整体掩码，含激活前已进上下文的历史明文（每次请求重掩）。
- **不防谁**：本机 agent（同权限；映射表可读；自适应探针可逼近）——「提升成本，不构成机密性边界」。
- **展示层**：助手文本流中的占位符在本机 UI/会话历史保持占位符形态（omp 无流拦截点，
  需求包 Don't #1）；工具执行与持久化不受影响。
- 模型占位符变形（全角化）→ 还原失败原样呈现；字面量 `[[CODE_N]]` 碰撞（极低概率）；
  自定义正则回溯成本自负；15 位一代证极低误报。

## 6. 测试计划

**单测**（bun test，移植 dsh-redact 用例子集 + omp 特有新增）：
- rules：五类命中/优先级重叠/幂等/校验码与 Luhn 负例/自定义规则编译失败跳过；
- mapping：一致性编号/分账隔离/持久化 round-trip/清理阈值；
- payload 掩码：§1.1 实测形状夹具（string content + block 数组 + tools.description）深遍历；幂等重掩；
- tool_call 还原：占位符还原替换/无占位符 no-op/派生字段安全网说明性用例；
- 配置：缺省默认/非法条目跳过/开关生效。

**端到端探针（容器，G1/G2 实证）**：
- G1：工作区放置含金丝雀敏感值（假手机号/假 sk- key）的文件 → 指示 agent 读取并复述 →
  扩展 debug 模式记录「本次请求掩码 N 处」+ 断言 N ≥ 1 且类别正确；（厂商侧不可直接抓包，
  以挂点出参为准——挂点返回值即实际发往 provider 的 payload，omp 契约保证）
- G2：指示 agent 用 bash `grep` 该金丝雀值并回显 → 断言 `tool_call` 还原后工具收到真实值
  （`tool_execution_end` 结果含真实值）且命令执行成功；
- 回归：扩展部署后现有 architect 工具四件套与 yuyi 工具面行为无变化（工具清单 diff）。
