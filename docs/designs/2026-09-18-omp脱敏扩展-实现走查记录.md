## 3. 端到端探针（容器真机，G1/G2 实证）

环境：容器 oh-my-pi（omp 18.1.18），扩展部署于 `~/.omp/agent/extensions/`，
`OMP_REDACT_DEBUG=1`。

金丝雀：容器内生成的 11 位手机号（138 段），落 `/tmp/canary.txt`。

会话任务：读取 `/tmp/canary.txt` → 用 bash `echo` 原样输出内容。

debug.log 实录：

```
MASK    session=default {"TEL":1}   ← 首轮请求：读文件结果（真实值）进上下文 → 掩码
RESTORE session=default tool=bash   ← LLM 工具调用参数（占位符）→ 还原为真实值 → bash 执行
MASK    session=default {"TEL":3}   ← 后续轮请求：历史明文重掩（含工具结果）
```

- **G1 出站掩码** ✅：两轮请求全部掩码（TEL 1 处 / 3 处），挂点返回值即实际发往
  provider 的 payload（omp 契约）——厂商侧收到的请求体零真实值；
- **G2 工具参数还原** ✅：LLM 生成的 bash 命令携带占位符，`tool_call` 还原后工具以
  真实值执行（echo 输出真实值），修订持久化到会话历史；
- **闭环观察**：模型最终回答只引用 `13812345678` 占位符——模型全程不知真实值，符合设计；
- 维护者视角注记：上述引文中的 `13812345678` 亦是本 dsh 会话脱敏插件对真实值的掩码视图，
  两层脱敏（dsh 会话层 + omp 扩展层）各自独立工作，互不干扰。

## 4. 排障记录（实现期真实缺陷与修正）

| # | 现象 | 根因 | 修正 |
|---|---|---|---|
| 1 | 断言两侧「显示相同」却 strictEqual 失败 | 维护者会话的 dsh-redact 对失败 diff 做了掩码——字面量金丝雀在维护者视图不可判 | 测试改为运行时金丝雀 + 结构化断言（§2 方法论） |
| 2 | 占位符形态的别名条目未被拒 | 首版字面量经写入路径变形（len 11 ≠ 9） | 该用例金丝雀同样改为运行时构造（`"[[TEL_" + "1]]"` 拼接形态规避转换） |
| 3 | hooks 测试 `maskText is not defined` | 漏导入 | 补 import |
