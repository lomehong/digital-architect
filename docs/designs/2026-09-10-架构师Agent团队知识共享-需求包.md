# 结构化需求包：架构师 Agent 团队的知识共享机制

> 产出者：architect-prd-digest（本建设会话代跑）· 日期：2026-09-10
> **状态（2026-09-11）：已关闭**——实现路线由《架构师协同御驿化需求包》（`2026-09-11-架构师协同御驿化-需求包.md`）承接；Q1–Q4 闭合结论见文末「附录：待确认闭合记录」
> 需求来源：主人（对话「多个架构师 Agent 组成团队，用什么机制共享各自掌握的信息」+ 七项边界澄清）
> 澄清七答（原话归并）：①跨实例跨机器 + 含 omp 宿主；②现阶段单 Owner（预留多 Owner）；③分组依据可能都包含（仓库/业务域/共享中间件）；④四个目的都有；⑤实时与按需都包括；⑥冲突应自动裁决；⑦按需同步。

## 可验收目标

1. 产出一份**跨架构师 Agent 的知识共享协议**规范（条目格式、发现索引、变更传播、冲突裁决、降级矩阵）；
2. 协议在**跨实例 + 跨宿主**（多 dsh 实例 + omp）下可运行，**不依赖任何单一宿主的服务注册表**（决策 D9 的直接应用）；
3. 四个共享目的（影响面分析/复用/一致性对齐/审计回顾）各有明确机制承接，逐一可指认；
4. 冲突在**事实层自动裁决且必留痕**，在**意图与取舍层强制人工**（六类决策门不可自动化）；
5. 拿不到兄弟知识的场景有显式降级，且**影响面分析不得默认无影响**（保守侧）；
6. 单 Owner 即可用；将来转多 Owner 只需收紧 `visibility`，不需重构条目结构；
7. 全程 git 管理，主人可按五问验收。

## 范围（做）

- 契约条目字段规范（key/facet/owner/consumers/version/supersedes/visibility/verify）；
- 发布面与索引联邦：`federation/` 目录规范（manifest/index/subscriptions/peers/changelog/contracts）；
- 变更传播：按需拉取为主 + 订阅通知为辅 + 读取时新鲜度校验；
- 冲突自动裁决分级表与留痕规则（含不可自动的边界）；
- 降级矩阵（无兄弟索引/无御驿/无 git/契约缺 owner）；
- 宿主适配补充：各 `adapters/<host>.md` 增「跨 Agent 共享」面；
- 三档验证方案（静态字段校验 / 机械结构检查 / 双 Agent 场景走查）。

## 不做项（Don't）

| # | 排除项 | 排除原因 |
|---|---|---|
| 1 | 多 Owner 隔离实现 | 现阶段单 Owner；只预留 owner/visibility 字段，不实现租户隔离 |
| 2 | 中心化共享数据库 | 违反联邦原则三（数据自治/单写者）；跨宿主不可达 |
| 3 | 知识全文互相同步 | 违反「引用不复制」与渐进披露；上下文成本与副本漂移双重代价 |
| 4 | 新建传输协议或新服务 | 复用御驿/git/HTTP；不新增服务与依赖 |
| 5 | 决策与承诺进共享面 | 治理类走账本 L2+ 与看板；共享面只承载事实 |
| 6 | 意图/取舍/承诺类冲突自动裁决 | 属六类人工决策门，任何机制不得代劳 |
| 7 | 实时消息总线/常驻复制 | 与「按需同步」冲突；新鲜度用读取时校验解决 |

## 专项评审触发

- **Cross-team Commitment**：索引联邦形态涉及跨仓约定（Q1）；
- **规则类知识变更**：冲突裁决分级表属规则类，按 `practice/suite-build-lessons.md` 教训须带真实案例回归；
- **合规/高风险**：无——纯文本规范 + 可选机械检查，不扩大权限面；
- **知识边界**：与宪章「分身不另建个人知识库」不冲突——本协议共享工程知识（architect-knowledge 面），非人格记忆。
