## 0. 一句话需求

给 omp 增加脱敏扩展：在「模型厂商边界」上做双向替换——出站请求（全部 messages + system）整体掩码为一致性占位符，LLM 厂商永收不到真实敏感值；`tool_call` 参数在工具执行前还原为真实值，agent 能力无感。本机会话持久化保留真实值。容器与 omo（自包含部署）双部署面。

## 1. 可验收目标（Acceptance）

| # | 目标 | 验收判据 |
|---|---|---|
| G1 | 出站掩码全覆盖 | `before_provider_request` handler 对 payload 深遍历掩码（messages[].content + system）；实测：挂点激活后向 LLM 发含已知敏感值的请求，抓取实际请求体断言零真实值、占位符在位；**激活前已进上下文的历史明文同样被重掩** |
| G2 | 工具参数还原 | `tool_call` handler 返回 `{input: 还原后参数}`；实测：诱导 LLM 生成含占位符的工具调用，工具 `execute` 收到的参数含真实值；且修订持久化到会话历史（omp 契约："becomes what the loop schedules, displays, persists"） |
| G3 | 一致性假名 | 同会话内同一真实值跨轮次/跨请求稳定映射同一占位符 `[[CODE_N]]`（首现顺序编号）；进程重启后（持久化恢复）映射保持一致 |
| G4 | 规则内置 + 可配置 | 五类内置规则默认启用（密钥凭据/身份证 GB 校验/银行卡 Luhn/手机号/邮箱，优先级递减、脱敏幂等）；规则文件可关闭类别、添加自定义正则与实体别名条目；自定义规则保存时编译校验 |
| G5 | 双部署面 | 容器：扩展落 `~/.omp/agent/extensions/` 并随会话加载；omo：vendor + install.sh 部署步，logstash-124 安装后 serve 会话同样生效 |
| G6 | 主人确认 | 自报 ≠ 完成；落定以主人确认为准 |

## 2. 范围（Do）

- **扩展本体 `omp-redact-extension.js`**（单文件 JS，yuyi 扩展同形态；源码落 digital-architect 仓，具体目录技术方案定）：
  - 规则引擎：移植 dsh-redact `rules.ts` 五类内置规则（含 GB11643 校验码、Luhn、数字边界防截取等细节）+ 优先级收集 + 重叠区间先到先得（密钥 > 证件 > 银行卡 > 手机 > 邮箱）+ 幂等；
  - 一致性假名映射：移植 `mapping.ts`（按会话分账、首现编号、占位符不重复命中）；
  - 持久化：移植 `persist.ts`（state.json、会话 7 天不活跃或总量超限自动清理对齐；文件权限 0600；加密存储列为 v2 后置增强——需先解决密钥管理）；
  - `pi.on("before_provider_request")`：payload 深遍历掩码 → 返回替换 payload（出站）；
  - `pi.on("tool_call")`：参数深遍历占位符还原 → 返回 `{input}`（入站还原·功能核心）；
  - 配置文件 `$HOME/.omp/redact/config.json`：总开关、类别开关、自定义正则（≤200 字符/≤50 条）、实体别名（≤100 条）；默认无配置 = 全内置规则启用；
- **容器部署**：扩展落 `docker/omp/agent/extensions/`（随现有挂载进 `~/.omp/agent/extensions/`），配置样例入库；
- **omo 集成（移交容器架构师）**：扩展 vendor 进 oh-my-ops + install.sh 部署步（同 yuyi 扩展模式）+ logstash-124 真机验证；
- **测试**：规则/映射/还原单测（移植 dsh-redact 测试用例子集，vitest 或 bun test）+ 容器端到端（真实 LLM 会话探针验证 G1/G2）；
- 走查记录落 `docs/designs/`。

## 3. 不做项（Don't）

| # | 排除项 | 原因 |
|---|---|---|
| 1 | 文本响应的展示层还原（UI/历史中占位符还原为真实值） | omp 无 LLM 流拦截点：`after_provider_response` 仅暴露 `ProviderResponseMetadata`（status/headers/requestId），无流访问（§5 实证）；安全方向退化：UI 见占位符，工具执行不受影响 |
| 2 | 防本机 agent | 权限模型决定（同用户同权限，映射表可读）；dsh-redact 威胁模型原文声明照搬：内容级遮蔽「提升成本，不构成机密性边界」 |
| 3 | 御驿跨 Agent 通信脱敏 | 决策 D2：只 LLM 出入站边界（御驿是自有 Hub，信任域内） |
| 4 | UI 设置页（dsh 版有 RedactSettingsTab） | omp 无对应 UI 体系；配置走文件（G4） |
| 5 | 日志打码（dsh 版 LoggerService exporter 挂点） | omp 日志体系不同，本版不做；v2 评估 |
| 6 | 探针行为审计（测试框高频/还原激增速率检测） | 有价值但非 v1 核心；登记 v2 |
| 7 | 持久化加密存储 | v1 明文 + 0600 权限；加密需先解决密钥管理，v2 增强 |

## 5. 可行性实证（2026-09-18，容器 omp 18.1.18 `dist/types/extensibility/extensions/types.d.ts` + `@oh-my-pi/pi-ai` dist 类型定义）

| 挂点 | 类型契约 | 结论 |
|---|---|---|
| `before_provider_request` | `ExtensionHandler<BeforeProviderRequestEvent, BeforeProviderRequestEventResult>`；`BeforeProviderRequestEventResult = unknown`（L789）；接口注释 "Can replace the payload" | handler **返回值即替换 payload** → 出站掩码可行 |
| `tool_call` | `ToolCallEventResult.input`（shared-events.d.ts L247-262）："Replacement input the tool executes with…becomes what the loop schedules, displays, persists"（model-issued 调用在 arg-prep 时触发，修订经 schema 重验后成为调度/展示/持久化的实际参数） | 工具参数**还原可行且修订持久化**（本机历史原文保留，与 dsh-redact 语义一致） |
| `after_provider_response` | `ExtensionHandler<AfterProviderResponseEvent>`（无 Result）；事件 extends `ProviderResponseMetadata = {status, headers, requestId, metadata?}`（pi-ai types.d.ts L166-171）——**无响应流访问** | 仅观测/审计用；入站流还原不可行 → 文本展示层还原登记为已知边界（Don't #1） |
| 扩展形态 | `ExtensionFactory = (pi: ExtensionAPI) => void \| Promise<void>`；`pi.on / pi.registerTool / pi.sendUserMessage`（yuyi 扩展实证同面） | 单文件 JS 扩展可行 |

## 7. 已知边界（继承 dsh-redact，随扩展交付明示）

- 正文恰好包含 `[[CODE_N]]` 形态字面量会被当作占位符（概率极低）；
- 助手文本消息中的占位符在本机 UI/会话历史保持占位符形态（Don't #1，安全方向退化）；
- 模型改写占位符形态（全角化等）→ 还原失败原样呈现（ASCII `[[CODE_N]]` 是回抄保真度最高形态）；
- 自定义正则回溯成本自负（内置规则全线性/定长）；
- 15 位一代证仅日期段合理性验证（18 位有校验码兜底）。
