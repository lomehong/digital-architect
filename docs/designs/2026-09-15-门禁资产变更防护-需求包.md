## 1. 可验收目标

1. CI 新增门禁步骤（gate-guard）：**受保护路径**出现变更、且变更提交未携带主人批准标记时，CI 红灯（error 阻断，与 knowledge-lint 同语义）；
2. 受保护路径清单（脚本内单一事实源，变更自身即受保护）：`.github/workflows/**`、`packages/architect-core/src/**`（评分器/规则/采集）、`dsh-architect/scripts/**`（门禁执行 CLI）、`docs/metrics/**`（基线 rubric）、`scripts/gate-guard.mjs`（本门禁自指保护）；
3. 批准标记约定：受保护路径变更的提交信息须含标记 **`Gate-Approved`**（主人口头/会话批准后由执行会话写入；标记真实性由主人巡检 CI 运行兜底——残余风险显式登记）；
4. 门禁本地可复跑（`node scripts/gate-guard.mjs <base> <head>`），CI 与本地同一实现；
5. 主人五问验收。

## 2. 范围（Do）

- `scripts/gate-guard.mjs`（零依赖 node 脚本）：输入 base/head → `git diff --name-only` → 命中保护清单 → 逐提交校验标记 → 报告与退出码；
- `.github/workflows/ci.yml` 增一门禁步骤（push 到 main 与 PR 触发；before 为空/新分支时回退比对 `HEAD~1..HEAD` 并告警）；
- 知识条目回写：红线提案从「提案」标「已落地」并在 source 补实证（确认后执行）。

| # | 排除项 | 排除原因 |
|---|---|---|
| 1 | GitHub Rulesets 强制 PR 流 | 平台级强管控会打断主人直推工作流；本轮只做 CI 软门禁 + 可见性，Ruleset 升级另议 |
| 2 | dsh-yuyi 多 token 演进 / 触碰御驿 | 既定边界（Yuyi 线另立需求） |
| 3 | 保护 `architect-knowledge/**`（知识内容面） | 知识条目走「待审核→主人确认」既有循环，与考卷资产不同层 |
