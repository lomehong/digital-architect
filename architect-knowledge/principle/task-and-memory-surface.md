# 任务面与记忆面契约（宿主无关）

> 核心主张：**看板是 dsh 的实现，不是方法论**。SKILL 只写「任务面操作名」，具体落点由适配层映射；
> 验收语义与留痕要求在任何宿主上都不放宽。

## 一、任务面（Task Surface）

### 五操作

| 操作 | 语义 | 谁可发起 |
|---|---|---|
| `create` | 立项：任务号 + 标题 + 可验收条目 + 动作级别 | 主人 / 架构师（受命后） |
| `claim` | 认领：把任务绑定到执行现场（会话/分支） | 执行方 |
| `report` | 自报：产出摘要 + 证据 + 未兑现项 | 执行方 |
| `confirm` | 确认落定：**只有主人可发起** | 主人 |
| `list` / `archive` | 查询与归档 | 任意（只读） |

### 状态机（不可跳步）

```
待执行 ──claim──→ 执行中 ──report──→ 待确认 ──confirm──→ 已落定
                     ↑                  │
                     └──── reject ──────┘
```

### 四不变量（任何宿主实现都不得放松）

1. **自报 ≠ 完成**：`report` 只把任务送入「待确认」；
2. **confirm 只能由主人发起**：实现必须记录来源（`confirmedBy` + `confirmedVia`），脚本拒绝无来源的确认；
3. **每步留痕可审计**：任务记录持久化（跨会话可查），非法跳步必须被拒而非静默放过；
4. **治理类动作未获授权即停**：push / 发布 / 删除数据 / 对外承诺——宿主有审批机制则走机制，无则强制询问主人，**不得静默放行**。

### 宿主实现映射

| 面 | dsh | oh-my-pi（omp） |
|---|---|---|
| 存储 | 看板服务（跨会话权威） | **文件台账** `目标项目/.architect/tasks/<taskId>.yaml`（git 管理） |
| 操作入口 | `task_delegate` / `task_claim` / `task_report` + 今日待办确认 | `scripts/task-ledger.mjs`（new/claim/report/confirm/list/archive） |
| 呈现 | 看板面板 + 今日待办 | `todo`（视图，非存储） |
| 人工确认通道 | 今日待办确认按钮 | `ask` 交互（结果写入 `confirmedBy/confirmedVia`） |
| 治理 | 账本 L0–L3（令牌 + 授权窗口） | 无账本 → 强制 `ask` + 台账登记授权字段 |

**落点选择依据**：目标项目内而非大脑仓——① 零挂载扩权（大脑仓为只读规则面）；② 任务痕迹归属被服务项目，团队可审计；③ 随项目版本化。

## 二、记忆面（Memory Surface）

### 最小契约

| 操作 | 语义 |
|---|---|
| `write` | 写入条目：内容 + 类型 + 陈述类型（事实/候选/…）+ 来源（origin/ref）+ 可见范围 |
| `read` | 按关键词/类型检索；默认只读当前有效版本 |
| `supersede` | 替代更新：生成新条目并双向链接旧条目，**历史保留可查** |
| `verify` | 标注验证状态（未验证/已验证 + 方法） |

### 两条不变量

1. **来源必填**：不得把「听说/转述」写成事实（转述御驿等消息一律 `候选`）；
2. **替代不删除**：更新走替代语义，历史可回溯（与看板/台账的留痕要求同源）。

### 宿主实现映射

| 面 | dsh | oh-my-pi（omp） |
|---|---|---|
| 存储 | dsh-memory（HTTP，条目 JSON） | memory bank（retain/recall 指针）+ **本仓 git 为权威** |
| 结构化知识 | 同上（master/self/public 可见性） | `architect-knowledge/` 条目文件（git） |
| 替代语义 | `entries/update` 替代 + 历史保留 | git 提交历史 + 条目内 supersede 注记 |

## 三、为什么这两面要抽象

- 现状（2026-09-11 之前）SKILL 与适配文件把 dsh 工具名当作通用语义写出，导致 omp 路径下**任务痕迹为空**（todo/task 均会话内），违反纪律二「一切知识进结构」；
- 抽象后：**方法论一套、实现两套**，新增宿主只需补一节映射（与适配五面框架同构）；
- 与 D9「核心不动、适配显式、降级保守」一脉相承：契约是核心，实现是适配，治理缺席一律收敛保守侧。
