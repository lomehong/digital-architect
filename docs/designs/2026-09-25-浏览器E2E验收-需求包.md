# 结构化需求包：架构师 Agent 真实浏览器端到端验收能力

> 来源：主人 2026-09-25 会话指令「我想要架构师 Agent 具有真实的端到端（跟人使用系统一样可以打开浏览器）测试的能力」，指定参考 browser-use/jev-ultrafast；因 TypeSafe Jev 模型不可用，主人指定开源替代 NandhaKishorM/laya。
> 前置实证：同日 Spike 已在本机全链路跑通（证据见下「六项覆盖检查表」）。Spike 产物在本机临时目录，未入仓、未入库（R9：知识库禁记设备路径）。

- **可验收目标**（可度量）：
  1. 架构师在验收环节能对目标 Web 系统（**隔离环境**）发起自然语言验收任务，由真实浏览器（Chrome，CDP 驱动）执行，产出可复跑证据：动作轨迹 JSON + 最终状态独立校验（URL/标题/页面文本，不采信模型自报 DONE）+ 可选截图；
  2. 能力基线不低于 Spike 实测：导航/筛选/表单类任务 3/3 稳定（15/15），七任务套件整体 71%（15/21）；已知失败类（搜索框打字、视口外分页）显式登记并在验收目标编写时规避；
  3. 全链路无数据出域：决策模型本地自托管（Laya v10s）、文本生成走已批准的 DeepSeek 端点、浏览器为本机/内网独立 Chrome 实例；
  4. 验收产出接入既有治理语义：结果 = 自报证据，主人确认才落定（验收语义跨宿主不变，不得弱化）。
- **范围（做）**：
  - 部署形态：本地/容器内 systemone 决策服务（Laya）+ 独立 Chrome 实例（独立 user-data-dir，不触碰主人浏览器）+ jev-ultrafast 循环（pin commit + `patches/jev-model.patch` 单 hunk：TYPESAFE_BASE_URL 端点与密钥容错）；
  - 能力封装：新增薄能力包（部署脚本 + 任务运行器 + 基线套件），并在 architect-implement 的验证手段中登记「浏览器验收任务」类型；
  - 适配层回写：`adapters/oh-my-pi.md` 工具面补浏览器能力映射；当前宿主（Kimi Code）适配缺口显式登记；
  - 供应链：权重与外部依赖全部 pin 版本/hash、仅 safetensors、来源登记；
  - 知识回灌：Spike 与首批验收经验沉淀 `architect-knowledge/practice/`（主人确认后）。
- **不做项**（显式排除）：
  - 不做确定性脚本回归框架（Playwright 用例生成是互补提案，不在本需求内）；
  - 不接 TypeSafe 云端 API（数据出域 + 当前不可用）；
  - 不做登录态突破/验证码绕过/密码填写（jev 设计上隐藏密码字段）；
  - 不对生产系统做带写操作的验收（写路径只指向隔离夹具/测试环境——suite-build-lessons:42 红线）；
  - 不自建协同/通知基建（D12：一律经御驿既有原语）；
  - 不为浏览器/决策服务创建登录自启或隐藏窗口常驻（suite-build-lessons:44 红线）。
- **假设**（标注依据）：
  1. Laya（Apache-2.0，代码+权重）与 jev-ultrafast（MIT）许可证兼容内部使用——依据：两仓 LICENSE；**待合规确认**；
  2. `cklxx/laya-browser` 权重（HuggingFace 个人账号发布）经供应链审查后可引入——**待确认（决策门 B1）**；
  3. 验收目标系统可提供隔离测试环境——待确认（逐试点确认）；
  4. CPU 推理（实测 0.9–3.2s/决策步）对验收场景可接受，GPU 为优化项而非前置——依据：Spike 实测。
