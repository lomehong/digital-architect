> 方法论依据：Yuyi 顶层架构设计 v0.2（通信平面定位与单一事实源红线）、《御驿-任务记忆层-设计》v0.2、《agent-org/御驿-Agent团队协作体系-设计》v1.0、`principle/host-neutral-core.md`、`principle/task-and-memory-surface.md`
> 准入结论：**通过**（目标 1–3 文档层已随本包交付；目标 4–8 依赖 Q1/Q2 拍板后实施，不阻断立项）
> **主人裁决（2026-09-11，身份模型纠正）**：dsh 与 omp 是两种宿主**类型**，不是两个 Agent；御符按 Agent **实例**签发（每实例一枚、严格独立），宿主类型是实例的运行环境**属性**而非身份；每种类型可有多个实例，`agent_name` 不嵌宿主类型。Q2/A2/目标 7 已按此改写；目标 4/5（接线）属宿主类型级基建，实例数量不影响其范围。`设备:agent_name` 寻址机制天然支持实例制，无需改御驿。

## 0. 背景：联邦草案撤稿对照（为什么不重造）

2026-09-10《架构师 Agent 团队的知识共享机制》草案（已撤销）为多架构师协同发明新基建；逐项对照，御驿均已有现成承接：

| 草案发明 | 御驿既有承接 |
|---|---|
| `peers.yaml` 成员清单 + 索引联邦（原 Q1「中心 vs 无中心」之争） | Hub roster：`yuyi_peers` 列出全部设备上可寻址会话；御符 `agent_name` 权威命名（同 owner 唯一），`设备:agent_name` 精确寻址 |
| 订阅通知 + `changelog.yaml`（原 Q2；假设 A2「omp 侧无御驿对应物」） | **假设不成立**：Yuyi 官方 omp 插件（10 工具，notify 可唤醒 + 请求-响应闭环 + 合并拉箱）；dsh 侧 `dsh-yuyi`（协议 v2，18 个 `yuyi_*` 工具）。通知 = `yuyi_send`（notify/mail），离线入箱不丢 |
| `changelog.yaml` append-only 留痕 | 任务记忆层 `~/.yuyi/tasks/<taskId>.jsonl`（append-only 七类事件，msgId 幂等，唯一真相源，带滚动压缩与留存纪律） |
| 契约条目 version/supersedes 版本机制 | 知识本体在 git（`architect-knowledge/`），版本即提交历史，替代语义已有纪律 |
| 冲突自动裁决分级表 | 不建协议：事实层回源核对（代码 > 已确认知识 > 实践记录，既有原则），意图层主人拍板（六类决策门）；过程分歧走 agent-org 评审委员会纪律（独立出意见 + 逐条对齐 + dissent 留痕 + 主评复核） |

**有保留价值并转移的资产**：契约条目最小字段（key/facet/owner/consumers/version/verify）可作知识条目格式增强——**另议**，不混入本包。
