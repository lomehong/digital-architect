## 1. 可验收目标

1. `architect-knowledge/principle/task-and-memory-surface.md` 就位（待审核入库，台账登记齐备，lint PASS）：任务面五操作 + 状态机 + 四不变量 + 记忆面最小契约；
2. `scripts/task-ledger.mjs` 可用：`new/claim/report/confirm/list/archive` 六命令；**非法跳步被拒**（如未 claim 即 report、未 report 即 confirm、自报后跳过 confirm 直接 archive 需显式理由）；零依赖 node；
3. 台账落点固定且 git 管理、可跨会话、可被评审引用（落点由方案 §2 论证定稿）；
4. CI 增台账结构校验 job（或并入既有 lint job），红绿双态自测通过；
5. `adapters/dsh.md` / `adapters/oh-my-pi.md` 的「任务执行」「记忆沉淀」两面改写为「契约 + 各自实现」；
6. 四个 SKILL 中写死的 dsh 工具名（`task_delegate`/`task_claim`/`task_report`/`ask_user`）改为**任务面操作名（按适配层映射）**，三副本同步经 `check-skills-sync.mjs`；
7. omp 侧实跑完整生命周期走查（create→claim→report→confirm→list）+ 非法跳步红态实测，记录落 `docs/designs/`；
8. 主人确认（自报 ≠ 完成）。

## 2. 范围（Do）

- 契约条目（principle）+ 台账 CLI 脚本 + CI 校验；
- 适配层两面改写（dsh 指向看板 API/工具；omp 指向文件台账 + ask 确认）；
- SKILL 工具名泛化（四个 SKILL × 三副本）；
- 生命周期走查与红态测试。

## 3. 不做项（Don't）

- **不改 dsh 看板自身实现**（套件仓零改动，契约只描述语义）；
- **不做跨设备任务同步**（dsh 看板与 omp 台账各自独立，不建同步桥；跨设备协同走御驿，另议）；
- **不实现记忆面宿主存储**（本次只定义契约 + 写明两宿主现状映射；omp memory bank/指针与 dsh-memory 均不改）；
- **不做 L2+ 审批自动化**（治理仍走各宿主既有机制：dsh 账本 / omp 强制 ask）；
- **不重构 docs/designs 存量文档**（不做历史回改）。
