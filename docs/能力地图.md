## 一、流程能力（五技能流水线：需求 → 方案 → 评审 → 实现 → 沉淀）

| 能力 | 一句话 | 入口/产出 |
|---|---|---|
| 需求准入（architect-prd-digest） | 模糊需求 → 结构化需求包：**需求拷问（grilling，3 轮上限，对齐后才准出）** + 六项覆盖检查 + 五问准入，不足处登记未知、不编造 | 产出 `docs/designs/*-需求包.md` |
| 技术方案设计（architect-design） | 渐进披露四层装载 → 架构链路分析 → Gap Analysis → 六维度+五问可执行方案；人工决策门命中即停问主人 | `docs/designs/*-技术方案.md` |
| 方案评审（architect-review） | 五问+六维度覆盖评分 + **双轴子代理评审（标准轴/规格轴，大 diff 并行）** + 证据回源抽查 + 知识漂移检查；**评审通过 ≠ 落定** | `docs/designs/*-评审结论.md` |
| 知识蒸馏（knowledge-distill） | 公众号文章/技术方案/串讲/复盘 → 五类知识条目 + 三台账同步，九步流程含 lint 强制 | 本知识库新增条目（首例：2026-09-11 腾讯文章两条） |
| 实现拆解（architect-implement） | 方案落定后的实现拆解与执行技能（**多票 ready-frontier 并行**；收尾含 retro 一问；详见其 SKILL.md） | `skills/architect-implement/` |
| 浏览器端到端验收（browser-acceptance，2026-09-25 落定） | jev-ultrafast + 本地 Laya System-1 决策 + 独立 Chrome——自然语言验收任务，产出可复跑证据（DONE 自报不算） | `browser-acceptance/`（README 有用法与红线） |

## 五、怎么用（新会话/主人入口）

- **有需求**：从需求准入起步（先出需求包再设计，勿跳步）；
- **新克隆/新机器**：先跑 `scripts/link-skills.ps1`（或 .sh）铺装宿主技能发现根链接，再进流程；
- **有文章/复盘要吸收**：走 knowledge-distill（九步，含 lint 强制）；
- **做影响面分析**：先读 map 索引 → 三仓 `.knowledge/dependencies.yaml` → 定点回源代码；
- **写方案**：对照 `templates/executable-design.md`，落定后在 `docs/metrics/` 追加内容分一行；
- **纪律三条**：自报 ≠ 完成；知识必带 source 且未确认不升级；提交前必跑 lint。
