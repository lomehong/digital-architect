## 3. 关键设计分叉：dsh 架构师承载形态（K1，待主人选）

**约束**（勘察报告 + Q4 裁决）：dsh-yuyi 御符是进程级——同进程两 preset 必然共享御符身份；主人红线禁止身份共享。故必须**进程隔离**：

| 选项 | 形态 | 优 | 劣 |
|---|---|---|---|
| **A（推荐）** | dsh 架构师 = **独立 dsh profile**（同机第二个 dsh 进程，如 profile `architect`），自有御符 | 身份干净；同机延迟低；复用宿主通用 preset 机制；与 omp 容器架构师构成跨宿主试点 | 多跑一个 dsh 进程（资源占用）；profile 生命周期管理 |
| B | dsh 架构师 = **另一台设备的 dsh 实例**（真跨设备，如 E:\code\nodejs\dsh 那台） | 最贴合御驿跨设备定位；同机零负担 | 需另一台设备就绪并常驻 |
| C | 暂缓 dsh 侧独立实例，先做 omp 架构师 ↔ Yuyi 线多 token 演进后再补 | 不新增进程 | 试点无限期延后；依赖 Yuyi 线排期 |

三选项均满足红线；**推荐 A**（试点最快闭环，身份最干净）。

## 4. 风险覆盖

| 风险类 | 分析与对策 |
|---|---|
| Compatibility | 新 preset 独立目录独立版本戳（勘察结论 2：戳按 preset 隔离天然工作）；分身零感知；删 preset 目录即回滚 |
| Exception | A1 双端互通未实测=试点首验项（需求包既定）；Hub 不可达→降级主人中转；**热重载竞态**（勘察风险）：物化器构建后删版本戳或先停进程再重物化 |
| Cache | preset 动态发现免重启（勘察结论 2）；无缓存面 |
| MQ | 通知可丢→mail 入箱；任务记忆层为唯一真相 |
| State | preset standing mount 每 id 一份（勘察结论 4）；版本戳=物化状态机 |
| Security | 御符每实例独立、明文不进仓（主人提供后注入 profile/容器配置）；旧路由 LAN 暴露注意（twin constraints 既定红线沿用） |
