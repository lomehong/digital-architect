# 证据采集收敛纪律

## 事故：同一现象被误判三轮

为"部署后用真实浏览器验证页面"开发 `ops_web_verify` 时，真浏览器探针始终报 **`404 证据缺失`**，而同一次运行里**控制台错误却采集到了**。排查走了两轮弯路：

| 轮次 | 假设 | 事实 |
|---|---|---|
| 1 | 采集代码笔误 | 打印采集原文后，`responses` 里只有主文档与 favicon，**确实没有那条 404** |
| 2 | CDP 事件路由/域未开 | 用**同一靶页**跑纯 CDP 脚本 + 等 3 秒：`title=status:404`，两条请求与两条 404 响应**全部在** |
| 3（真因） | 读取窗口太早 | 探针在 ~500ms 就读证据；页面那条 `fetch` 的响应**晚于**该窗口 ⇒ 固定 250ms 静默窗口不足，页面侧 Resource Timing 也尚未落账 |

结论：**不是采集逻辑错，而是"读得太早"**——用固定 sleep 当"等异步证据就绪"的手段，本质是拿时序赌正确性。

## 纪律一：异步证据要等"状态收敛"，不要睡固定时长

- 读网络/异步证据前，等**在途状态收敛**（如 CDP 跟踪 `requestWillBeSent`/`loadingFinished`/`loadingFailed`，待"在途请求数 = 0"持续 N 毫秒）。
- **必须设上限**：长轮询/SSE 类站点"在途永远非 0"，等满会拖垮结论（本项目取 3s，超时即继续，证据仍在）。
- **第二证据源互补**：CDP 事件 + 页面侧 `performance.getEntriesByType('resource')`（同源带 `responseStatus`）取并集——单一来源在时序边界上必然有盲区。

## 纪律二：环境能力缺口 = 可执行指引，不是崩溃，也不是静默降级

浏览器/依赖不可用时，工具必须返回**结构化失败 + 具体启动命令**（本项目给出 docker/本机/远程三种起法），让调用方一眼可行动。同理适用于任何"外部运行时缺席"的场景。

## 纪律三：失败路径要显式记失败断言（空集合恒真的陷阱）

"端点不可达"最初被判成 **ok=true**——因为断言集合为空，`[].every(pass)` 恒真。任何以"断言全过"为通过判据的裁决，**必须在失败路径显式补一条失败断言**，否则"什么都没验证"会被伪装成"验证通过"。

## 防止复发

三条纪律各自落成回归：假会话单测（有 / 无错误、断言矩阵、不可达路径）+ 真浏览器契约探针（起 Chromium+CDP 全链，且**无浏览器环境显式 SKIP 而非静默通过**）。
