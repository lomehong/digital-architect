## 0. 五问速答

| 问 | 答 |
|---|---|
| 需求 | 平台脱离大脑仓独立常驻运行；大脑仓多副本经 git 同步 |
| 系统 | observatory 平台 + 大脑仓（git 多副本）+ N 台实例宿主（omp/dsh/…） |
| 证据 | 2026-09-12 真实性审计：13 数据源中 6 个依赖仓内文件或本机执行（知识库/评审队列/台账 CLI/告警规则/数据根配置/平台代码本身） |

| 验证 | 每阶段端到端实测（含认证负测），延续本平台既有验证纪律 |

## 1. 现状依赖（为什么现在离不开仓）

平台代码本身随仓分发之外，运行期读取仓内：知识库与评审队列、`alert-rules.yml`/`data-roots.yml` 配置、治理经本机 CLI 执行台账、`--tasks` 台账目录。事件/身份/审批/御驿/审计已是独立数据面（上报式或数据根内）。

## 2. 目标架构

| 面 | 现状 | 目标态 |
|---|---|---|
| 数据面 | 事件契约（文件+认证 HTTP）✅ 已实现 | 不变——**事件契约是唯一真实数据面** |
| 配置 | 仓内 yml | 迁至 `<数据根>/config/`（仓内文件降为缺省模板）；寻址顺序：数据根 → 仓 |
| 知识面 | 直读仓内目录；升级=改仓内文件 | 平台持有大脑仓 **git 镜像**（fetch/pull 只读展示；升级=镜像内 commit+push，多副本经 git 同步）；git 为权威 |
| 治理面 | 本机执行 task-ledger CLI | **治理指令单**（管理员令牌 + 幂等单号）→ 目标宿主 governor agent 领单本地执行 → 回执事件上报；平台本地 CLI 降级为同宿主优化 |
| 打包 | 随仓 | 独立发布（tarball/npm 包，同 dsh-architect 发布形态），任意机器可部署 |

## 3. 分期

- **C1 打包与配置解耦（✅ 完成 baf41a8）**：平台独立发布；配置寻址改数据根优先。验收：在无仓目录启动全功能。
- **C2 大脑仓 git 镜像（✅ 已实施待主人确认）**：知识面独立。验收：镜像机上看板全量条目；知识升级经 commit+push 落到远端。回归：`observatory/contracts/brain-mirror-e2e.mjs`。
- **C3 治理远端执行面（governor）**：实例宿主部署 governor（御符 token 认证 + 指令单签名 + 命令白名单 + 幂等 + 回执事件）；平台治理改发指令单。验收：跨主机 confirm 端到端 + 负测（伪造指令单被拒）。
- **C4 迁移手册**：现役数据根与配置迁移步骤。

## 4. 风险与防线

| 风险 | 防线 |
|---|---|
| governor = 治理接管面 | 御符 token 认证 + 指令单单号幂等 + 命令白名单（仅 task-ledger/文档 status）+ 全量回执留痕；**不使用计划任务/隐藏窗口**（杀软教训） |
| git 凭据 | 最小权限 PAT（仅大脑仓）；凭据只进平台进程环境 |
| 双写不一致 | git 为知识权威；平台镜像冲突时拒写并呈报主人 |

## 5. 明确不做

平台多实例高可用（单台常驻足够）；数据库化（保持零依赖文件契约）；governor 通用命令执行（只做治理白名单）。

## 6. 待主人确认

① 分期顺序；② 部署目标形态（NAS/云主机/常开 PC）与大脑仓 git 远端位置；③ C3 governor 的宿主清单。
