## A. 前置分析（证据层）

### A.1 设计空间定界（关键结论）

容器实证材料（`2026-09-14-lint隔离上下文感知-实证材料.md`）的三型边界样本（后缀文本 / 整串切分 / 版本类引用）经核读现行 core 后定性为**旧核解析差异**——现行 `relativePathCandidates`（lint.ts L107-112）按空白/标点切分、后缀自然剥离、无扩展名不入候选，三型均已自愈。**不在本方案范围**（随 omp-architect 换核自然消失）。

**本方案唯一范围**：①隔离上下文识别条件扩展（`.snapshot` 之外增活仓快照探测）；②容器脚本路径 junction 物化修复。

### A.2 既有机制（Reuse 对象）

- `makeRefExists(root, {soft})`：soft 模式缺失 → undefined → warning 不阻断（kbcollect.ts L137-148）；
- `lintKnowledgeAt` 快照自动识别：`knowledge/.snapshot` 标记 → R4/R5/R7 宽松（kbcollect.ts L154-158）；
- R7 三基准解析：KB 根 / 仓库根 / 条目所在目录（kbcollect.ts L136）——容器内「仓库根」=/opt/architect，KB 外 ref 必然失败（A1 实证）；
- CI 物化先例：dsh-architect `8ff370f`（npm ci 后物化 core 进 node_modules）。

### A.3 探测条件与物化定稿（评审 Gap-1/Gap-2 吸收后）

**隔离上下文判定优先级（有正向证据才降级，无则维持 hard）**：

1. **显式覆盖**（opts.isolated / CLI `--isolated[=false]` / env）——最高优先，可双向强制；
2. `.snapshot` 标记（既有，生产快照）；
3. **正向证据探测**（三条件同时满足才判隔离）：①父目录无 `.git`；②**KB 根五类目录齐**（meta/principle/scenario/practice/reference——证实是真实 KB 快照而非残缺导出）；③无仓根级目录 `docs/`。任一不满足 → 维持 hard。

残余面收敛：导出的完整仓残片（无 .git 但 docs/ 在）→ hard ✓；残缺导出（KB 不全）→ hard ✓；仅剩的「完整 KB 且无 .git」形态**本就是隔离 KB 上下文**（KB 外 ref 客观上不可达）→ soft 是正确行为而非误判。
**降级必须可见**：warning + 备案计数输出行（供 CI 阈值化）。
负向单测守两条：「无 .git 但有 docs/ → hard」「无 .git 且 KB 不完整 → hard」。

**物化漂移守护（Gap-2）**：物化产物带版本戳（core package.json 版本 + 内容哈希）+ 构建期**新鲜度断言**（与 packages/architect-core 不一致即 fail）+ 副本头注「构建生成、勿手改」。
