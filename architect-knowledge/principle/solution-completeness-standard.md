# 可执行方案标准与完备度度量（95% 的语义）

> 与 `executable-design-six-dimensions.md` 的关系：该条目定义六维度清单，本条目定义**可执行性的内容标准**与**完备度度量的语义**——「结构分 ≠ 内容覆盖度」。

## 可执行方案六要素（§6.5，缺一即只是「改动清单」）

1. **仓库范围与范围外参与方**：哪些仓必改、哪些只读不改、哪些必要但不在本方案内——否则出现「每个人都以为别人会做」的空档；
2. **术语对照与代码现状**：PRD 语言 / 业务语言 / 配置名 / 服务名 / 代码名逐一映射，防搜索漏项；
3. **复用 / 改造 / 新建组织 Gap**：复用必须确认用户、规则、状态、权限、风险语义一致；改造说明扩展点与存量兼容；新建要证明现有能力无法承载；
4. **影响分析**：被改函数的调用方、异常传播、必须逐字节不变的存量行为；
5. **验证矩阵（不只单测）**：新增 API→契约测试；改状态机→核心流程；改消息→生产/消费兼容；改缓存→失效与降级；灰度配置→开关关闭时的存量回归；
6. **未知显式登记**：待确认项不是方案不完整的证据——无法证实的内容被明确登记，才说明没有把推断伪装成事实。

## 完备度 95% 的语义（§6.6）

- **不是**预知所有线上情况、任何需求不需人确认；
- **是**：在需求完成准入、关键知识可回源、代码与配置得到核查、人工评审完成之后，方案对主要工程问题的**六维度内容覆盖度**足够高；
- 前提三件套：原始需求完整度相对较高 + 知识库体系完备 + 一流基模；
- 剩余不确定性通常来自：跨团队决策、外部系统行为、数据口径、产品取舍——**本就不应由模型单独决定**；把它们压缩成少量明确问题，而不是以隐性风险藏在方案里。

## 度量口径对本仓的适用声明

本仓 `dsh-architect/coverage.ts` 的 0-60 分是**结构分**（章节存在 / 空单元格 / 占位符），不度量内容覆盖度；内容覆盖度需人评（母包 P2-1 提案，未立项）。评审时两者不可互替。
